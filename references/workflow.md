# 从问题到成片

## 用户入口示例

> 用 $science-video-studio 做一个零基础也能看懂的机械表计时视频，3 分钟，精密机械风，16:9，自然中文旁白。先让人认清发条、轮系、擒纵和摆轮，再看一次能量传递；输出 MP4、字幕、交互版与来源。

> 用 $science-video-studio 解释 TCP 三次握手，工程蓝图风，5 分钟。标明客户端与服务端状态、SYN/ACK、初始序列号和重传，区分连接建立与应用数据传送。

> 只比较白底展品、纸艺和杂志信息图风，沿用同一段内容，暂时不做配音。

## 工程结构

每个选题单独目录，至少包含：

```
brief.json             # 观众、学习结果、画幅、风格、档位、交付范围
science-gate.json      # 陈述覆盖、独立复核、问题关闭与资产锁定
science-review.md      # 可读的修订与验收证据
sources.json           # claim ID → 来源 URL/定位/核验情况/简化
lesson.json            # 旁白、音频文件、画面对象、动作
shots.json             # 教学目的、片段绑定、景别、相机、剖切、版式与转场
src/model.mjs          # 状态/运动/数值，同一事实源
src/scene.*            # 空间场景、cameraAt(t)、布局与 setTime
audio/                 # 分段配音
build/timeline.json    # 实测时间轴
build/captions.srt
build/narration.wav    # 有声模式产生
preview.html
final.mp4
qa.json                # 实际检查、结果、未验证项
```

不是每次都要停下来请求确认：用户已有明确授权时直接推进。首次探索风格可以先交预览；用户要求成片时继续完成音频、合成和检查，不用“方案完成”代替成片。

## 科学表达检查

正式成片按 [科学审校](scientific-review.md) 做配音前与成片后两轮核验，并保存问题、修订及未验证项；不能仅确认视频可播放。

- 每个关键结论至少能追到一个可靠来源；机械结构优先厂家技术材料，协议优先 RFC，算法优先原论文/官方文档。非显而易见的事实不能只靠视觉推测。
- 真实结构、示意简化、类比分开记录。必要的“未按比例/慢放/省略部件”写到画面小字。
- 演示速度可变，但画面读数必须使用同一个模型时间。不可同时显示真实转速与不成比例的运动而无说明。
- 机械齿轮：齿数/角速度/旋向同一约束；啮合齿形与中心距也需检查。视觉上接触不证明能制造。
- TCP：不要把第三次确认简单表述成“确认双方网络永远可靠”；真实状态、序列号和超时适用条件分别解释。
- 神经网络：可用已知小矩阵展示一次前向计算，不需要为了真实性自动训练新模型。

## 叙事与画面节奏

先读 [3D 与镜头编排](cinematic-direction.md)。在 brief 中分别记录 render_mode（3d/hybrid/2d）、选择理由、视觉风格与观众任务；风格不是渲染维度。空间主题的默认主画面是 3D，二维曲线/状态图是按需出现的辅助。若选二维主画面，记录它为何更准确或更易读，不能仅因为实现更快。

不要把章节按钮、固定大标题、常驻曲线栏和四格总结卡原样烧录成全片模板。模型占屏比例、视角、局部特写、对照和信息密度应随讲解问题改变；播放控件留在交互页外层。

先给问题和完整对象，用一次可辨认的变化吸引注意。名称只在首次引入时解释；镜头里同一时刻通常一个主焦点。每段都回答“这是什么、现在发生什么、为什么相关”中的一个问题。重要因果用慢放、停顿或对比重放，不能只靠旁白口述。

9:16 需要重新排布与加大局部特写，不是裁剪 16:9。口播字幕优先单行，长句按语义拆成先后显示的短字幕；不能靠缩小字号塞进一行。给平台 UI 和字幕留安全区域。六种风格的模型身份、来源和讲解顺序保持一致，以便真正比较风格。

## 完成记录

写清：已生成哪些文件、是否有声、实际时长、用过的服务/音色、哪些关键事实核验过、实际使用真实 3D/等轴测/二维中的哪一种、哪些画面仍是简化示意，以及相机运动与局部重点的检查结果。时间与成本仅按实测或当次供应商信息报告，不复述文章中的 1% 周额度或固定 90 分钟。
